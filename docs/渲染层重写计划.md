**遇到的两个类型坑**（记下来，后面谁再碰会有用）

1. `$<T extends Element = HTMLElement>()` 在 `w = $('#x')`（赋值给联合类型变量）这种位置，
   TS 5.9 会把泛型回退到**上界** `Element` 而不是默认值 `HTMLElement`，表现为「属性全没了」。
   解法：这类赋值点显式写泛型 `$<HTMLElement>('#x')`；属性访问点（`.textContent` 等）不受影响。
2. `catch (err)` 在 `strict` 下是 `unknown`，`err.message` 编译不过。
   统一收进 `util.ts` 的 `errMsg(err): string`，顺带覆盖「抛出物不是 Error」的情况。

**顺手修掉的两处**（都属于「旧代码里明确意图但没接上」，不是新增功能）

- `switch:view` 事件：`collector.ts` 与 `subscribe.ts` 都在发（「填入发布框」按钮），
  但旧 `app.js` 只订阅了 `reload:connection`，没人接 —— 点了按钮主题被填进发布页输入框，
  **页面却不切过去**。现在 `app.ts` 里 `on('switch:view', switchView)` 接上，实测切页生效。
- `publish.ts` 里 `S.on('topics:changed', () => {})` 是空监听，删掉。

**几个决定**

- **不引 Tailwind 的 preflight**。只 import `theme.css` + `utilities.css`。
  现有组件样式全写在语义类上，preflight 会改 `input`/`button`/`table` 的默认盒模型，
  逐条对齐的收益远小于风险。工具类仍然可用（`@theme` 的令牌 + `source` 扫描都正常）。
- **图标数据从 `lucide-react` 里取，但不引 React**。`lucide-static` 是额外依赖，
  而 iconNode 就是纯数据；脚本按 JSON 之外的形式求值（lucide 的属性键不带引号），
  取出来序列化成 TS。阶段 3 引 React 时，这份数据可以直接给 `lucide-react` 用。
- **`@theme` 的颜色值写成 `var(--bg)` 而不是色值**。CSS 变量运行时解析，
  切主题只是换 `:root[data-theme]` 那一组，不用重新生成 CSS，也不会出现两套色值漂移。
- **`.icon { pointer-events: none }`**。否则点击事件的 `e.target` 会是 `svg > path`，
  视图里凡是基于 `target` 的判断都会失效（e2e 里点表格行就是这类路径）。
- **`table-layout: fixed`**。列宽从「按内容自动」改成「按表头声明」，
  消息列表每秒上千条时列不会随内容左右跳。代价是主题/预览两列必须给百分比宽度，
  否则会被压缩成等分的两半。

**踩到的坑**

1. Tailwind 的内容扫描会把源码里出现的词当成类名，于是生成了 `.table{display:table}`、
   `.list-item{display:list-item}`、`.grid{display:grid}`、`.filter{…}` 这些**与业务类同名**的工具类。
   当前没出事，是因为手写样式不在 `@layer` 里（无层样式优先于任何层）。
   但阶段 3 若把组件样式挪进 `@layer components`，这些同名工具类就会反过来盖住它们 —— 迁移时要先改名。
2. `.select` 上加 `flex: none` 会把它撑满整行：它有 `width: 100%`，不收缩就吃光
   `.pane__actions` 的宽度，把搜索框和按钮全挤出去（日志页顶部工具条整条消失）。
   工作台那种「输入框吃剩余宽度」的场景，要用 `.pane--workbench .field__row > .select { width: auto }`。
3. `@theme` 的变量**只在被工具类引用时才输出**到产物 CSS，所以构建后用
   `grep --color-accent` 查不到是正常的，不是没生效。

- `npx vite build` → 16 modules → 47.1 kB js + 28.3 kB css（CSS 从 19.7 kB 涨到 28.3 kB，
  增量是 Tailwind 默认调色板与令牌变量）

**与计划不同的三处**

1. **不需要 `<LegacyMount>` 适配器**。内容区本来就是静态骨架，旧视图不需要先挂载到
   React 里再操作；只有顶栏和导航需要「响应式」，用 portal 投递到既有布局槽位即可，
   DOM 结构和 CSS 一行都不用改。
2. **`components/` 只做了 `Icon` 与 `Button`**。`Input`/`Select`/`Modal`/`DataTable` 这些
   只有在视图改写成 React 之后才有意义 —— 现在就建，等于给一个还没存在的调用方写空壳。
   Radix 与 `sonner` 同理，一并留给阶段 4。
3. **`store/state.ts` 保留为门面**。视图是两千行命令式代码，直接改成
   `useAppStore.getState()` 收益为零、风险全在；用 Proxy 转发 get/set 之后，视图
   一个字都不用改（`state.messages` 读到的就是当前快照，赋值就是 `setState`）。

**踩到的坑**

1. **React 与旧视图抢同一个节点**。`Rail` 的两个角标原先由 `collector.render()` 和
   `log.updateBadge()` 手写 `textContent`，React 又按 store 渲染同一节点 —— 谁后写谁生效，
   表现为「角标偶尔不刷新」。现在只留一个写入方（React），旧的写入点已删。
2. **`#btnServerNew` / `#btnServerEdit` 双份处理器**。这两个按钮归 `TitleBar` 的
   `onClick`，`servers.init()` 里再加一次 `addEventListener` 就会连开两次弹层，
   看起来像「点了没反应」。已从 `init()` 里移除。
3. **`state.connections.set()` 是静默写入**。旧代码 `syncConnectionState()` 直接改 Map，
   引用不变 → zustand 收不到通知。改用 `lib/connection.ts` 的 `reloadConnection()`，
   内部走 `upsertConnection` 换新 Map。
4. **`.btn--icon` 被 flex 压成 22.5px**。连接条里两个图标按钮宽度写死 28px，
   但作为 flex 子项会被收缩；加 `flex: none` 才稳。
5. **`<select>` 的 flex 基准尺寸与排版宽度不一致**。`.select` 的 `width: auto` 让基准取
   内容宽度（实测 220），实际排版 231，差的 11px 从 `gap` 里扣，图标按钮就贴上选框圆角了。
   `.conn-group > .select` 定死 240px 后基准与结果一致。
   —— 这两条是同一个教训：**尺寸写死的控件不能靠 flex 自动分配**。

| `components/Field.tsx` / `Empty.tsx` / `Toggle.tsx` | 33 / 12 / 34 | 表单字段、空态、复选框与开关 |

**与计划不同的四处**

1. **`collector` 与 `subscribe` 合并成一个 `WorkbenchView`**。计划里是两个视图分别迁移，
   但它们是同一个界面（左树右表），拆开反而要跨组件传「订阅动作」「选中消息」。
   合并后「点主题 → 订阅 → 右侧出数据」这条主链路在一个组件内闭环。
2. **消息表用 `@tanstack/react-virtual`，但跑在 `<table>` 里**：上下各放一个占位 `<tr>`
   撑出滚动高度，只有窗口内的行是真实 DOM。`ROW_HEIGHT = 28` 必须与
   `.table tbody td { height: 28px }` 同步改，否则滚动条长度会漂。
3. **主题树不虚拟化**。树上千节点，但滚动频率远低于消息表；全量渲染换来展开/折叠零延迟，
   构树用 `useMemo` 缓存，折叠态是 store 里的 `Set`。
4. **四个视图常驻挂载，只切 `is-active`**。卸载重挂会丢掉虚拟列表位置、树的折叠态与
   详情面板高亮，而这些恰恰是用户切页时最不希望变的。

**踩到的坑**

1. **视图隐藏时虚拟列表一行都不渲染**（容器高度为 0）。这不影响使用，但 e2e 若在别的
   视图上断言 `msg-row` 必然为 0 —— 断言前要先切回该视图。已写进 e2e 注释。
2. **受控输入让「直接改 `.value`」失效**。`input.value = 'x'` 只改 DOM 不进 store，
   点「发布」发出去的还是旧值。e2e / 截图脚本统一改为「原生 setter + 派发 input/change」。
   这不是取巧，是受控组件的定义。
3. **弹层 resolve 必须只认一次**。`dialog.*` 同时只允许一个请求，后来的直接拿 `null`；
   否则两个请求共用一个 resolve 会串台（关第一个弹层时把第二个请求也结算了）。
4. **`#serverSelect` 的选中项要兜底到第一项**。配置被删或首次导入时 store 里是 `null`，
   界面若显示第一台而 store 是 null，点「连接」会得到「未配置服务器」。用 effect 同步。

**为什么是 `bundle:false` 而不是打包单文件**：`tools/test-manager.mjs` 要 `require('dist/main/mqtt-manager.js')` 在裸 node 里跑 33 项测试。打包成单文件后它会被揉进 `main.js`，一 require 就把 `electron` 拉进来，那条独立测试通道直接失效 —— 这正是计划里点名要保住的性质。逐文件转换还顺带让「源码文件 ↔ 产物文件」一一对应，堆栈行号也对得上。

**契约收紧（编译期就报错的那一类）**

1. `INVOKE.mqttEncoding` 的入参从 `string` 收紧成 `PayloadEncoding`。渲染层本来就只传三种字面量，之前靠 `string` 蒙过去。
2. `subscribe` 的「扫描过滤器恰好等于已订阅主题」分支原来 `return true`，但通道契约声明返回 `ConnectionState` —— 渲染层若用这个返回值就会拿到布尔。现在统一返回 `serialize(ctx)`。

**踩坑记录**

1. **`.mjs` 里没有 `require`**：`tools/build-main.mjs` 首版直接 `require('./lib/build-main.js')` 就 `ReferenceError`，得走 `createRequire(import.meta.url)`。
2. **`IClientOptions.protocolVersion` 是字面量联合 `3 | 4 | 5`**，`Number(cfg.protocolVersion) || 4` 推不出联合，需要一次断言（运行时值不变）。
3. **`IClientOptions` 没有 `alpnProtocols` 字段**（mqtt.js 内部读的是 `ALPNProtocols`）。这里是「用户填了原样透传」的历史行为，不能因为类型缺失就悄悄丢掉，改用 `Record<string, unknown>` 显式透传并写明原因。
4. **preload 需要 DOM lib**：它要写 `document.documentElement.dataset.platform`。`tsconfig.main.json` 因此带 `lib: ["ES2022","DOM"]`，文件里已注明「`src/main/**` 不许用 DOM API」。
5. **`dialog.showMessageBox(mainWindow, ...)` 的窗口参数可能为 null**：Electron 运行时按 `options == null` 判断，传 null 等价于「无父窗口」，是既有行为。类型上补一次断言，不改成条件分支。
6. **`mainWindow` 是模块级 `let`**：在 `ready-to-show` 等回调里 TS 不会窄化。`createWindow` 改用局部 `const win` 持有窗口，回调都闭包引用它，避免非空断言散落各处。

**已知残留**：`loadRenderer` 的第三档兜底（`loadFile(src/renderer/index.html)`）在阶段 3/4 之后已经失效 —— `src/renderer/index.html` 只挂 `main.tsx`，ESM 在 `file://` 下会被 Chromium 拦。留着它是为了「没构建时窗口仍能打开、能看主进程日志」，正常使用请先 `npm run build`。这一档未做删除，因为改动它属于行为变化，不在本阶段范围内。

## 0. 一页摘要

现有渲染层是 17 个文件约 5000 行的原生 HTML/CSS/JS：无构建步骤、`window.X` 全局命名空间、手写 DOM 拼接、`file://` 直接加载。

问题不在「原生 HTML 做不出好看界面」，而在三处具体的东西：

1. **观感**：图标是 Unicode 字符（`↑ ⌗ ◍ ≡ ◐ ⚙ ＋`），13px 微软雅黑，缺 hover/active/focus 态与层次感。
2. **维护**：视图之间靠 `window.X` 约定耦合，改一处要通读调用方；DOM 拼接散落在各视图里。
3. **契约**：`preload.js` 暴露的 7 组 35 个方法、6 个事件通道，与 `api.js` 的封装是两份手工维护的镜像，没有类型约束保证一致。

重写方案：**React + TypeScript + Vite + Tailwind v4 + Radix**，生产加载从 `file://` 换成自定义 `app://` 协议，切 6 个可独立合并的阶段（见 §6）。

阶段 1+2 完成，界面就已经现代化了；阶段 3~6 买的是代码可维护性与测试可靠性。

**现有依赖保留**：`mqtt@5.14.1`（主进程用）、`electron@28.3.3`（见 §11 待确认事项 2）。

### 4.2 为什么是这套

- **React 而非 Vue**：本项目的 UI 主体是数据密集表格、树、JSON 详情面板，Radix / TanStack Virtual / 图表生态在 React 侧最完整。Vue + Naive UI 上手更快、观感也不错，作为备选保留。
- **Radix 而非成品组件库**（Element Plus / Ant Design）：现有 `app.css` 已经是一套成型的 CSS 变量设计系统，套成品组件库会为了迁就它的默认视觉而丢掉这套体系；Radix 只给行为与可访问性，样式完全由我们控制。
- **Tailwind 而非继续手写 CSS**：1582 行手写 CSS 的问题是新增组件时无处安放；设计令牌段（`:root[data-theme]`）本身就是「主题变量」，可以直接映射成 Tailwind 的 `@theme`，是**迁移**而不是推倒。
- **Zustand 而非 Context + useReducer**：现有 `state.js` 已经是「单一 state + 派生函数 + 事件总线」结构，Zustand 能一比一映射，且主进程事件推送写入 store 不需要 Provider 包裹。

### 5.2 数据流（无环）

```
视图组件 ──读写──> Zustand store ──invoke──> ipc/client.ts ──> window.xmqtt
   ▲                                                                  │
   │                                                          contextBridge 白名单
   │                                                                  │
   └──订阅──────────────── store <──事件推送── 主进程 ipc ──> mqtt-manager ──> broker
```

单向：**命令上行**（store → client → preload → 主进程）与**事件下行**（mqtt-manager → preload → store）是两条独立通路，不存在回环。

主进程仍是**唯一真相源**（连接状态、订阅表、主题集合只在主进程维护一份）。渲染层 store 只持有「主进程推过来的快照 + 纯界面态」（选中项、过滤词、折叠态、主题）。这条边界不因重写而改变。

### 5.3 IPC 契约集中化

`src/shared/channels.ts` 定义通道常量，`src/shared/models.ts` 定义领域模型；`src/renderer/ipc/client.ts` 用类型化签名包一层，`global.d.ts` 声明 `window.xmqtt` 的形状。

阶段 1 完成后，主进程仍用 JS（靠 JSDoc 引用可选），但渲染层一侧已经是强类型。阶段 6 把主进程迁 TS 后，两端共用同一份定义，契约漂移在编译期就暴露。

  - `app.whenReady()` 前 `protocol.registerSchemesAsPrivileged([{ scheme: 'app', privileges: { standard: true, secure: true, supportFetchAPI: true, stream: true } }])`

dev 模式必须单独放宽（Vite HMR 需要连 `ws://localhost:<port>` 并注入内联脚本），做法是**只在 dev 构建注入放宽版 CSP，生产产物保持严格版**，两者不共用一份 meta。

**验证顺序（关键）**

1. **先打穿协议 + CSP**：最小页面（一个 `app://` 下加载的 `<script type="module">` + 一段 CSS + 一次 `window.xmqtt.invoke`）跑通，再动其他代码。这一步不过，后面全白做。

4. `node tools/e2e-test.mjs` → 29 项全绿。

## 7. 关键决策（ADR）

**ADR-01 · 生产加载用 `app://` 自定义协议，不用 IIFE 单文件**
`file://` 下 ESM 被 CORS 拦（实测/README 均记录）。IIFE 单文件能避开，但会牺牲 code splitting、动态导入，且把打包产物压成一个大文件。`protocol.handle` 注册 privileged scheme 是 Electron 官方推荐做法，`webSecurity` 不用关，CSP 的 `'self'` 正常生效。
**代价**：`main.js` 要改加载路径；`data:` 与相对路径解析行为要逐个验证。

**ADR-02 · 构建目标锁定 Electron 内核**
`Electron 28.3.3 → Chromium 120`，`vite build.target` 设 `chrome120`。设低了（如默认 `es2020`）会触发不必要的降级转换，实测出现过 `esbuild` 报「解构无法降级到 chrome87」的构建失败；设高了则新语法在旧内核上崩。**升级 Electron 时必须同步改这个值。**

**ADR-03 · UNC 盘只放源码，构建产物与缓存放本地盘**
实测 UNC 小文件写比本地慢 10.7 倍，而 `node_modules` 是几十万小文件。`vite.cacheDir` 指向本地盘；`optimizeDeps` 预热后日常 HMR 只读源码（几十个文件），UNC 影响可接受。**具体放置策略见 §11 待确认事项 1。**

**ADR-04 · 状态边界不因重写而改变**
连接状态、订阅表、主题集合仍然只在主进程维护一份，渲染层 store 只放「快照 + 纯界面态」。这条是现有 `AGENTS.md` 的约定，也是最容易在重写中被打乱的地方（一旦渲染层开始本地推断连接状态，就会出现两处真相）。

**ADR-05 · 测试门面：`data-testid` + `window.__xmqtt`**
现有 e2e 依赖 `window.X` 内部对象与 30 个硬编码选择器。React 化后 `X.state.activeConn()` 这类路径必然消失。
方案：dev/test 构建注入 `window.__xmqtt`（暴露 `store.getState()`、`actions`、`api`），并为所有可交互元素加稳定的 `data-testid`。
迁移节奏：阶段 1 双轨并存（旧 `window.X` 保留，新门面挂上）→ 阶段 4 每视图迁移断言 → 阶段 5 删除旧 `window.X`。
**为什么值得**：class 与 id 会随重构漂移，`data-testid` 不会；把「测试怎么观察应用」收敛到一个门面，比重写后再靠选择器碰运气可靠得多。

**ADR-06 · CSS 迁移而非重写**
`app.css` 的 `:root[data-theme]` 段本质就是设计令牌，直接映射成 Tailwind `@theme`；组件样式段在阶段 2–4 逐步搬到组件内。不做「全部推翻重写」是因为那 1582 行里已经有打磨过的细节（滚动条、聚焦态、离线置灰），推翻会丢。

**ADR-07 · 主进程本阶段不动**
`mqtt-manager.js` 是唯一真相源且不依赖 Electron，33 项测试跑在它上面。重写渲染层期间它是**不变量**——一旦它也被改，测试失败就分不清是渲染层还是 Manager 侧的问题。

> **适用范围到阶段 5 为止。** 阶段 6 把这几个文件迁到了 TS，但迁移严格是「加类型、不改逻辑」：
> `mqtt-manager` 的判断分支、批量窗口、通配符匹配、扫描行为全部照搬，33 项测试继续全绿就是证据。
> 唯一的行为级改动是 `subscribe` 在「扫描过滤器已存在」时返回 `ConnectionState` 而不是 `true`（对齐契约，见阶段 6 交付清单）。

## 8. 测试策略

| 类型 | 覆盖场景 |
| --- | --- |
| happy | 连接 → 扫描主题 → 点主题订阅 → 收消息 → 发布 → 模板保存 → 导出 CSV/JSON |
| 错误 | broker 不可达、连接中途断开、TLS 校验失败、订阅失败、发布失败、导入非法 JSON、导出取消 |
| 边界 | 每秒千条 + 5000 条缓冲上限、`#` 全量订阅、主题树上千节点、超长 payload、2000 条日志上限、消息 0 条时详情面板空态 |
| 界面 | 深浅主题、离线态统一置灰、窗口缩放（minWidth 1080）、模态与 toast 的焦点管理、`Esc` 关闭 |
| 回归 | `test-manager` 33 项作为主进程不变量，全程必须全绿 |
| 单测（新增） | store 裁剪逻辑、主题增量合并、树构建、订阅状态派生 |

**执行顺序**：改渲染层后至少跑 e2e；单独改 store 逻辑时先跑单测再跑 e2e。

## 9. 风险与应对

| 风险 | 触发条件 | 应对 |
| --- | --- | --- |
| `app://` 下 CSP 挡住脚本 | 阶段 1 首验 | 先用最小页面打穿；不行则退回 `protocol.handle` + 显式 `Content-Security-Policy` 响应头，而非 meta 标签 |
| UNC 盘构建慢到不可用 | 阶段 1 起 | `cacheDir` 与 `node_modules` 移本地盘；仍慢则整个项目迁本地盘（见 §11） |
| e2e 在阶段 4 失去回归网 | 每步删旧视图时 | ADR-05 的门面必须**先于**任何视图 React 化就位；每视图迁移断言后才允许删旧文件 |
| Radix Portal 与 `titleBarOverlay` 拖拽区冲突 | 阶段 3 模态 | 顶栏保持 `-webkit-app-region: drag`，Portal 挂在 `body` 之外不受影响；模态打开时验证顶栏仍可拖拽 |
| 升级 Electron 导致 `--no-sandbox --disable-gpu` 适配失效 | 若采纳 §11 建议 | 单独一次提交只做 Electron 升级并重跑全套测试，不与渲染层重写混在一起 |
| 双重节流导致消息显示延迟 | 阶段 4.5 | 渲染侧不加节流，只消费主进程批次；在 store 里断言批次长度 |

## 10. 明确不做

- **不改主进程 MQTT 逻辑**：`mqtt-manager.js` / `ipc.js` / `store.js` 保持现状（阶段 6 可选迁 TS，但不改行为）。
- **不改配置文件格式**：`%APPDATA%\XMQTT Tool\xmqtt-config.json` 结构不变 → 回滚不涉及数据迁移。
- **不改 preload 白名单**：7 组 35 个方法、6 个事件通道原样保留。
- **不引入在线服务 / API key / 第三方账号**：这个工具全程本地。
- **不做 UI 功能增删**：本次是重写，不是加功能。任何新功能另开一轮。
- **不动测试专用依赖**：`aedes`（本地 broker）仍是测试专用。
